# План проекта «Where'd It Go» — учёт расходов

Этап 1 из 6. Здесь только план, кода пока нет.

**Версия 4: личная версия.** Сайт делаем пока только для одного человека с тремя устройствами: iPhone, iPad и ноутбук на Windows. Данные хранятся на самих устройствах и синхронизируются через Яндекс Диск. Сервер и база данных не нужны. Общую версию для друзей и родственников сделаем позже на основе этой (раздел 9).

Почему передумали: в октябре 2026 года Яндекс Облако работает в аварийном режиме после атак на дата-центры, а бесплатной базы данных у других российских провайдеров нет. Для одного пользователя сервер не нужен, поэтому мы ни от какого облака не зависим, и всё бесплатно.

## 0. Принятые решения

| Вопрос | Решение |
|---|---|
| Пользователи | Пока одна: ты. Регистрации и входа нет |
| Устройства | iPhone, iPad (Safari), ноутбук на Windows (Chrome или Edge) |
| Где хранятся данные | На каждом устройстве, в браузере (IndexedDB), плюс общий файл на твоём Яндекс Диске для синхронизации |

## 1. Как это устроено

```
 iPhone                 iPad                   Ноутбук
 ┌───────────────┐     ┌───────────────┐      ┌───────────────┐
 │ сайт (PWA)    │     │ сайт (PWA)    │      │ сайт          │
 │ IndexedDB:    │     │ IndexedDB:    │      │ IndexedDB:    │
 │ полная копия  │     │ полная копия  │      │ полная копия  │
 └──────┬────────┘     └──────┬────────┘      └──────┬────────┘
        │   синхронизация, когда есть интернет        │
        └──────────────┬──────┴───────────────────────┘
                       ▼
        Яндекс Диск: Приложения/<название>/data.json

 Файлы самого сайта (HTML, JS, CSS) скачиваются с GitHub Pages
 и запоминаются на устройстве, поэтому сайт открывается и без интернета.
```

### Термины

- **Фронтенд** — часть сайта, которая работает в браузере. В личной версии весь сайт — это фронтенд, сервера нет.
- **IndexedDB** — база данных, встроенная в каждый браузер. Сайт может хранить в ней много записей прямо на устройстве. Данные одного сайта не видны другим сайтам.
- **PWA (Progressive Web App)** — сайт, который можно «установить» на главный экран. Он открывается без адресной строки, как приложение, и работает без интернета.
- **Service worker** — небольшой скрипт, который браузер держит «в фоне». Он сохраняет файлы сайта на устройстве, чтобы сайт открывался и без сети.
- **API** — набор команд, через которые одна программа работает с другой. У Яндекс Диска есть API: «скачай файл», «загрузи файл».
- **OAuth** — стандартный способ дать сайту доступ к твоему аккаунту без передачи пароля. Ты входишь на странице Яндекса и нажимаешь «Разрешить». Сайт получает **токен** — ключ с ограниченными правами (у нас только папка приложения на Диске).

## 2. Технологии

| Что | Чем | Зачем |
|---|---|---|
| Язык | **TypeScript** | JavaScript с типами: многие ошибки видны ещё в редакторе, до запуска |
| Интерфейс | **React + Vite** | React — самая популярная библиотека для интерфейсов, по ней много учебных материалов. Vite собирает проект и мгновенно обновляет страницу при правке кода |
| Хранение на устройстве | **IndexedDB через библиотеку Dexie** | Без Dexie работать с IndexedDB неудобно. Dexie ещё и сама обновляет экран, когда данные меняются |
| Синхронизация | **REST API Яндекс Диска** | Бесплатно, место на Диске у тебя уже есть. Я проверил: API принимает запросы прямо со страницы сайта (CORS разрешён), сервер не нужен |
| Диаграммы | **свои компоненты на SVG и CSS** | Кольцо и столбики простые, без библиотеки цвета берутся прямо из темы, а сайт легче. Цвета проверены на различимость при нарушениях цветовосприятия |
| PWA | **vite-plugin-pwa** | Сам создаёт service worker и описание значка (manifest) |
| Тесты | **Vitest** | Проверяем то, где легко ошибиться: деньги, подсчёт статистики, слияние данных при синхронизации |
| Шрифт | **Manrope**, файлы шрифта лежат в проекте | Геометрический шрифт, как на референсах, с кириллицей. Не зависит от сторонних серверов |
| Хранение кода | **Git + GitHub** | Работает из России, регистрация без карты |
| Размещение | **GitHub Pages** | Бесплатный хостинг для сайтов из файлов, с HTTPS. Обновление: `git push`, дальше GitHub Actions (автоматические задачи на серверах GitHub) сами собирают и выкладывают сайт |

**Альтернативы:**
- *Только локально, без синхронизации*: проще, но на трёх устройствах были бы три разные копии.
- *Google Диск вместо Яндекс Диска*: тоже возможно, но для доступа к Диску Google требует регистрировать приложение в Google Cloud, а Яндекс Диск надёжнее работает из России.
- *Свой сервер и база*: это и есть будущая общая версия (раздел 9).
- *Размещение на Netlify, Vercel или в Яндекс Облаке вместо GitHub Pages*: всё возможно, выбор не критичен. GitHub Pages проще всего, потому что код и так будет на GitHub. Если GitHub Pages окажется недоступным с твоего телефона, на этапе 5 выберем другое.

## 3. Синхронизация через Яндекс Диск

### Подключение (один раз на каждом устройстве)

1. В профиле нажимаешь «Подключить Яндекс Диск».
2. Открывается страница Яндекса, ты входишь в свой аккаунт и разрешаешь доступ **только к папке приложения**. Остальные файлы на Диске сайту не видны.
3. Сайт получает токен и хранит его на этом устройстве (токен действует около года).

Перед этим, на этапе 5, нужно один раз зарегистрировать приложение на `oauth.yandex.ru`. Это бесплатно, проведу по шагам.

⚠️ **Особенность iPhone и iPad.** Когда сайт установлен на главный экран, вход через страницу Яндекса иногда не возвращается обратно в приложение. Запасной вариант уже предусмотрен: Яндекс показывает код, ты копируешь его и вставляешь в сайт. Это нужно один раз на каждом устройстве.

### Как сливаются данные

- У каждой записи (расход, категория, источник, карта) есть уникальный `id` и время последнего изменения `updatedAt`.
- Удалённая запись не стирается сразу, а помечается `deleted: true` («надгробие»). Так другие устройства узнают, что её удалили, а не «забыли».
- Синхронизация: скачать `data.json` → для каждого `id` оставить более свежую версию → сохранить у себя → загрузить объединённый файл обратно.
- Когда запускается: при открытии сайта, через несколько секунд после каждого изменения и кнопкой «Синхронизировать» в профиле. Рядом видно «Синхронизировано: 2 минуты назад».
- Без интернета сайт работает как обычно, изменения уйдут при следующей синхронизации.

**Почему ничего не теряется:** каждое устройство хранит полную копию. Даже если два устройства загрузят файл почти одновременно и одно затрёт изменения другого, второе при следующей синхронизации вернёт их обратно.

### Новое устройство

На первом запуске сайт сначала предлагает **«Подключить Яндекс Диск»**:
- если на Диске уже есть данные, они скачиваются, и экран выбора источников не нужен;
- если данных нет, или ты нажала «Пропустить», открывается выбор источников (Стипендия / Зарплата / Родители / свой вариант).

**Защита от дублей:** у 11 стандартных категорий и трёх предложенных источников постоянные `id` (например, `cat-products`). Даже если начать на двух устройствах независимо, после синхронизации «Продукты» не задвоятся. Если же на двух устройствах вручную создать одинаковую новую категорию, после синхронизации будет две. Одну можно удалить, перенеся расходы во вторую.

### Особенность Safari

Safari может стереть данные сайта, если им не пользоваться 7 дней, но только для сайтов, открытых во вкладке. Сайт, установленный на главный экран, это правило не затрагивает. Кроме того, сайт попросит браузер хранить данные постоянно, а копия на Яндекс Диске страхует в любом случае. Ещё одна особенность: у установленного на экран сайта своё хранилище, отдельное от вкладки Safari. Поэтому подключать Диск нужно именно в установленном приложении.

## 4. Структура данных

Записи устроены так же, как таблицы в будущей базе данных, поэтому при переходе к общей версии данные перенесутся без переделок.

Принципы:
- **Деньги в копейках, целым числом** (`1 250,50 ₽` → `125050`). В компьютере 0,1 + 0,2 = 0,30000000000000004, а с целыми копейками таких ошибок нет.
- **Расход хранит id категории, источника и карты, а не их названия.** Переименовала категорию — новое имя сразу видно во всех старых расходах.
- **Дата расхода — просто дата, без времени**, по часам устройства. Месяц определяется по дате расхода, поэтому с 1-го числа итог сам начинается с нуля.
- **id** — случайные строки (UUID), у стандартных категорий и источников — постоянные.
- У каждой записи есть `updatedAt` и `deleted` для синхронизации.

| Хранилище | Поля |
|---|---|
| **categories** — категории | `id`, `name`, `createdAt`, `updatedAt`, `deleted` |
| **sources** — источники денег | `id`, `name`, `createdAt`, `updatedAt`, `deleted` |
| **cards** — карты (никаких номеров) | `id`, `bank` (обязательно), `name` (необязательно), `createdAt`, `updatedAt`, `deleted` |
| **expenses** — расходы | `id`, `amountKop` (> 0), `categoryId`, `sourceId`, `cardId?`, `title?`, `spentOn` (`2026-10-16`), `createdAt`, `updatedAt`, `deleted` |
| **settings** — настройки (синхронизируются) | `onboarded` (выбраны ли источники), `lastSourceId` |
| **device** — настройки этого устройства (не синхронизируются) | тема, токен Яндекс Диска, время последней синхронизации |

Индекс `spentOn` у расходов — чтобы быстро выбирать расходы за месяц.

### Как устроены операции из требований

- **Подсказки названий:** уникальные названия из твоих расходов (без учёта регистра и пробелов по краям), самые частые — первыми.
- **Удаление категории или источника, к которым привязаны расходы:** сайт спрашивает, куда перенести расходы, переносит их и помечает категорию удалённой. Всё это одной **транзакцией** (операцией «всё или ничего»).
- **Удаление карты:** у расходов убирается привязка к карте, карта помечается удалённой.
- **Первый запуск:** создаются 11 стандартных категорий. Источников нет, пока ты их не выберешь.

## 6. Дизайн

### Что я взял из референсов

- **светлый фон и белые карточки** с большими скруглениями (~20–24 px) и мягкой тенью; на тёмной теме — тёмно-зелёные карточки, как в примере 3;
- **одна яркая «главная» карточка** (как в примерах 1 и 3): в ней **итог за месяц** крупной суммой на лаймовом фоне;
- под итогом — сравнение со всем прошлым месяцем: «55 % от сентября (15 200 ₽)» и тонкая полоска-прогресс. Когда траты превысят прошлый месяц, полоска становится заметнее и появляется надпись «больше, чем в сентябре»;
- **кнопки-«таблетки»** (полностью скруглённые) и **круглые кнопки-иконки**;
- **кольцевая диаграмма** (круговая с дыркой в центре, как в примерах 2 и 3), в центре итоговая сумма;
- **столбчатый график** по дням со скруглёнными столбиками; выбранный день — лаймовый, остальные — приглушённые (пример 3);
- **боковое меню** на широком экране (примеры 1, 2, 4).

| Назначение | Светлая тема | Тёмная тема |
|---|---|---|
| Фон страницы | `#F4F6EF` | `#06231D` |
| Карточки | `#FFFFFF` | `#0C342C` |
| Основной текст | `#0C342C` | `#FFFDEE` |
| Второстепенный текст | `#4E655E` | `#A9C2B8` |
| Главная кнопка («Добавить») | `#076653`, белый текст | `#E3EF26`, текст `#06231D` |
| Главная карточка (итог месяца) | градиент `#E3EF26 → #E2FBCE`, текст `#0C342C` | `#E3EF26`, текст `#06231D` |

**Темы:** по умолчанию сайт берёт тему из настроек устройства. В профиле и в меню есть переключатель ☀️ / 🌙, и выбор запоминается на этом устройстве. Все цвета задаются **CSS-переменными** (именованными значениями вроде `--color-card`) в файле `tokens.css`. Тема меняется подменой набора переменных.

### Что в референсах неудобно на телефоне или противоречит требованиям

| Проблема | Решение |
|---|---|
| Все примеры — для широкого экрана | На iPhone нижняя панель и одна колонна (см. таблицу выше) |
| Лаймовый `#E3EF26` на белом почти не читается (контраст 1,3 : 1 при норме 4,5 : 1) | Лайм только как фон под тёмно-зелёным текстом (контраст 10,8 : 1) или как цвет на тёмной теме |
| В палитре только оттенки зелёного, а категорий 11 — куски диаграммы сольются | Для диаграмм набор из ~10 различимых цветов: зелёные из палитры плюс фиолетовый, оранжевый, голубой, розовый (как в примере 3). Точные суммы всегда видны в таблице |
| Подсказки при наведении мыши не работают на сенсорном экране | Подсказка появляется по касанию |
| 31 столбик по дням на узком экране | Тонкие столбики, подписи только у каждого 5-го дня, значение — по касанию |
| Мелкий светло-серый текст (пример 4) | Второстепенный текст не светлее `#4E655E`, шрифт не меньше 14 px |
| Большой календарь (примеры 4 и 5) | Кнопки «Сегодня / Вчера» и системный выбор даты |
| Поиск в шапке, колокольчик, аватарка, «Upgrade to Pro» | Этого нет в требованиях, не делаю. Поиск по названию — только в списке расходов |

### Главное действие — добавить расход за пару касаний

«＋» открывает **выезжающую снизу панель**: сразу появляется цифровая клавиатура для суммы, категории — плитками-«таблетками», источник по умолчанию тот, что был в прошлый раз. Получается: «＋» → сумма → категория → «Сохранить». Название, карта и дата необязательные, они ниже.

Этот стиль используем на всех этапах.

## 7. Бесплатно ли это и надолго ли хватит

| Сервис | Ограничение | Нам нужно |
|---|---|---|
| GitHub Pages | 1 ГБ на сайт, 100 ГБ трафика в месяц | ~2 МБ сайта, трафика — мегабайты |
| Яндекс Диск | Бесплатно 5+ ГБ (обычно у тебя уже есть место) | Файл `data.json`: ~100 байт на расход, то есть 10 лет по 100 трат в месяц — около 1,2 МБ |
| IndexedDB на iPhone и iPad | Сотни мегабайт и больше | Те же ~1 МБ |

Платить ни за что не нужно, карта не нужна.

## 9. Как потом сделать общую версию

Всё, что мы делаем сейчас, останется:
- **интерфейс, дизайн, статистика, диаграммы, CSV** — без изменений;
- **`src/data/repo.ts`** — единственный файл, который знает, где лежат данные. Сейчас он работает с IndexedDB, в общей версии будет обращаться к серверу;
- **данные**: структура совпадает с таблицами будущей базы, поэтому твои расходы перенесутся одной загрузкой файла.

Что добавится: сервер, база данных, регистрация и вход (с подтверждением почты и защитой от подбора пароля), смена пароля, удаление аккаунта, кнопка «Поддержка» с Telegram и запасной копией на почту. Где разместить сервер и какую взять базу (YDB в Яндекс Облаке или PostgreSQL у другого провайдера), решим тогда по ситуации. Все наработки по этой части сохранены в истории git: в версии 3 этого файла (коммит «План v3»).
